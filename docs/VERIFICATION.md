# 검증 기록

2026년 10월 11일에 격리된 테스트용 Home Assistant에서 확인했습니다. 운영 Home Assistant에는 접속하지 않았습니다. 코드와 문서 작성에 AI를 사용했으며, 아래 결과는 실제 실행과 화면 관찰을 기준으로 작성했습니다.

## 버전 차단 제거 후 로컬 회귀 검증

Core·Frontend 버전과 entrypoint 해시를 설치 조건에서 제거한 뒤 Node 테스트 93개와 Python 테스트 15개가 모두 통과했습니다. 실패하거나 건너뛴 테스트는 없습니다. 미래 버전 직접 설치, 낡은 pin과 변경·혼합·누락 해시, pin과 hass 버전 문자열 없이 시작하기, 빌드 관측 실패와 official auto 라우터 생성을 테스트했습니다. 새 설정 생성기는 pin을 출력하지 않습니다.

이번 변경은 합성 설정과 SDK fake로만 검증했으며, 운영 HA나 테스트용 HA에 접속하거나 배포하지 않았습니다. 버전이 달라도 적용을 시도한다는 동작을 검증했지만, 미래 HA의 내부 계약이나 실제 SDK 화면까지 검증한 것은 아닙니다. 기존 실제 화면 검증 결과와 당시 버전은 아래에 그대로 보존합니다.

## 이전 자동 테스트

- Node 테스트는 90개가 통과했고 실패한 테스트는 없었습니다. 키가 들어 있는 랩 설정 파일을 저장소에 넣지 않으므로 해당 테스트 1개는 건너뛰었습니다.
- Python 테스트는 15개가 모두 통과했습니다.
- 이 테스트는 가짜 SDK를 사용하므로 실제 지도 인증과 화면 검증을 대신하지 않습니다.

## 실제 SDK와 HA 화면

- HA의 그룹화 버튼을 눌렀을 때 NAVER 지도를 유지했고, 안전 모드로 바뀌지 않았습니다.
- 서로 가까운 합성 마커 3개를 만들고 NAVER와 Google에서 각각 그룹 아이콘 1개로 표시되는 것을 확인했습니다. 그룹화를 끄면 같은 제공자를 유지했습니다. 임시 아이콘 생성기를 사용한 검증이며, HA 기본 아바타 그룹 모양을 모두 검증한 것은 아닙니다.
- Google 지도는 지도 카드의 테마를 다크와 라이트로 바꾸었을 때 `colorScheme`이 각각 `DARK`와 `LIGHT`로 바뀌었습니다. 실제 화면에서도 어두운 배경과 밝은 배경을 확인했습니다.
- 검증이 끝난 뒤 합성 마커를 제거했습니다. NAVER 자동 전환 상태로 복원했습니다.

## NAVER 공식 스타일 검증의 한계

테스트용 설정에 사용자가 지정한 라이트·다크 스타일 ID를 넣었습니다. 실제 SDK에서 `customStyleId`가 테마에 맞는 ID로 바뀌는 것을 확인했습니다. 이 ID는 저장소 기본값에 넣지 않았습니다.

그러나 자동화 브라우저에서 NAVER의 `Util.glSupported()`는 false를 반환했고, 지도 옵션의 `gl`도 false였습니다. 따라서 이 환경에서는 기본 래스터 지도만 표시되었습니다. 스타일 ID를 전달했다는 사실만으로 커스텀 스타일의 실제 렌더링을 검증했다고 판단하지 않았습니다.

브라우저의 렌더러는 SwiftShader였습니다. GL을 지원하지 않는 정확한 원인은 확정하지 않았습니다. 하드웨어 가속을 사용할 수 있는 일반 브라우저에서 `gl`이 true인지 확인하고, 라이트·다크 스타일이 실제로 표시되는지 추가로 확인해야 합니다. CSS 필터로 지도를 변형하거나 제공자 로고와 저작권 표시를 숨기지는 않았습니다.

## HACS 검증의 범위

패키지 구조, 상대 import, 설치 경로, 체크섬과 캐시 버전의 일관성을 테스트했습니다. HACS가 업데이트할 때 키 설정 파일이 패키지 폴더 밖에 남도록 구성했습니다.

실제 HACS 설치와 GitHub Actions의 HACS 검증 결과는 별도로 확인해야 합니다. 패키지 테스트가 통과했다는 사실을 HACS 기본 저장소 등록이나 실제 설치 성공으로 설명하지 않습니다.

## 초기 로딩

한 번의 새로고침에서는 HA 지도 클래스가 준비되는 동안 메서드 검사에 실패하여 확장을 적용하지 않았습니다. 다시 새로고침하자 확장이 설치되었습니다. 실패 시 원래 지도를 유지하는 동작은 확인했지만, 모든 초기 로딩에서 확장이 먼저 설치된다고 보장하지 않습니다.
